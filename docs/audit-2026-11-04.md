# Jobsearch 1.0.0 candidate: agent architecture audit

Scope: local uncommitted candidate for Claude Code and the generated conservative Codex edition, against the approved onboarding/egress addenda. Audit used the ai-agents-architect skill. Reproductions use synthetic profiles and temporary repositories only. No network uploads, applications, destructive commands or real profile edits were executed. The engine was evaluated through decision functions and subprocess hooks, not by asking a model to assert compliance.

## Confirmed findings and repairs

| Priority | Finding before repair | Repair and verification |

The initial suite of 367 passing tests did not cover these adversarial cases. The first new regression run had 13 failing/erroring tests. Twenty-one focused audit regressions now cover these cases and related scope/format checks. Tests that previously expected Bash permission asks for direct tracker/final-CV mutation were corrected to enforce the stronger existing read-only/editor-only rules. The complete suite is run again before hand-over.

## Policy decisions confirmed and implemented

The user chose both conservative recommendations after the audit:

1. **Absolute draft-only delivery.** Recognized send/reply/apply/submit actions deny before destination grants in both clients. Browser/computer click/type/fill/submit actions in the job-search project also deny; the user interacts manually. Draft creation and separately approved non-message document writes remain available (Claude asks; Codex requires manual execution).
2. **Default denial for unclassified connectors.** Unknown connector names and generic executors such as `js`, `execute` and `request` deny even with an exact grant or GET/read hint. Exact built-in read classifications are maintained in `hooks/egress.py`; adding one requires source review. Supported explicit mutation names continue through the existing exact-grant gate, excluding generic executors. Classified read inputs are checked for configured personal values.

Regression checks exercise grants, operation hints, failure handling, drafts and both host packages without sending or uploading anything. These decisions close the two policy blockers; live client installation and onboarding checks remain unverified.

## Established limitations, not new approval requests

- Codex's conservative deny/manual behavior and hosted-web preflight limitation were already explicitly chosen. Hooks do not intercept hosted web search, and a model could skip a procedural preflight.
- First chat confirmations and private repository visibility are user attestations. The hook does not verify them by querying private services.
- Arbitrary/obfuscated programs, process startup failures, hook trust, timeouts and race windows between a permission check and an external tool write are not an OS security boundary. Do not run concurrent first-time onboarding against the same files. Stronger guarantees require host filesystem/network/tool restrictions.
- The wizard and semantic grounding are model-guided workflows. Doc/unit checks cannot prove that a model will never skip a step, infer a false fact or mishandle a real CV. Skill eval JSON files are cases, not recorded successful model runs.
- Fresh installation, hook trust UI, full new-profile onboarding/update in both clients and real-board scanning are NOT VERIFIED in this audit. No publication or automatic installation is performed.

## Reproduce without domain expertise

From the repository root:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_connector_policy.py' -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_audit_regressions.py' -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -q
python3 -B evals/validate_repo.py
```

Expected: the audit tests end in OK; the complete suite ends in OK; the validator has zero failed checks. Publish-gate identity checks require the user's private config; a WARN skip is not a privacy pass. The independent YAML audit used an already installed PyYAML solely for verification; it is not a plugin dependency.
