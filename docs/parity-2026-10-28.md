## 3. Rank parity: procedural, NOT a live plugin run

Procedural parity (a subagent following `commands/rank.md` step by step), not a live plugin run. The live `/jobsearch:rank` run is the owner's Task 14 step 5. No URL was fetched. The vacancy text came from the copy's stored application vacancy summaries; the saved ranked files for these rows predate the plugin format and hold no raw description.

Per row: duplicate verdict from `tracker_edit.py find` (new script, owner config, copy), repost from `repost_check.py`, blockers from the typed `blockers` list of the config (10 items) checked against the stored vacancy text.

| Row | Saved dup verdict | New `find` now | Dup | Saved blockers | Typed blockers | Blockers |
|---|---|---|---|---|---|---|
| 1 | ALREADY APPLIED | ALREADY APPLIED (same URL/job id) | same | none confirmed | none fire; salary and hours Unknown | same |
| 2 | ALREADY APPLIED | ALREADY APPLIED | same | none confirmed (test task type unknown) | none fire; salary Unknown | same |
| 3 | ALREADY APPLIED | ALREADY APPLIED | same | none ("Middle-to-Senior" is a range, not a Middle label) | none fire; the Middle keywords do not match a range | same |
| 4 | NOT APPLIED at check time (applied later the same day) | ALREADY APPLIED | different, expected (time) | hard: mandatory test automation plus Playwright in duties | no hard fire; no SDET, coding-challenge or framework-ownership wording | different (see below) |
| 5 | NOT APPLIED at check time (applied later) | ALREADY APPLIED | different, expected (time) | none | none fire | same |

- Row 4 and 5 duplicate verdict: the tracker now contains the application that happened after the check. Re-running `find` against a copy of the tracker with those two rows removed (emulating check time) gives NO MATCH / NOT APPLIED for both, equal to the saved verdicts. So the lookup logic agrees; only the data moved.
- Row 4 blockers: the saved file calls "mandatory test automation and suite maintenance, Playwright in duties" a hard blocker. The owner's own rule text, mapped 1:1 into the config, is narrower: mandatory SDET or coding challenge, or automation framework ownership. The vacancy lists test automation as a requirement and Playwright tests as a duty, but not those three things. So the typed blockers do not fire. This is a difference between the saved verdict (a wider reading by the earlier session) and the config as written, not a script bug. Decision for the owner: keep the config as is (the saved reading was applied by judgement, the applied-anyway outcome supports it), or add a wider rule. A broad keyword such as "test automation" would also fire on rows that only list automation as a nice-to-have, so it is not recommended as a hard keyword.
- Row 4 side note: the keyword item for the BA role matches a sentence that only says the team works with a Business Analyst. `rank.md` asks for a check against what the vacancy states, so a reviewer should judge the role is not BA-oriented. Same as the saved verdict (no BA blocker), but a pure keyword match would false-positive here.
- Repost check: for all 5 rows the only hit is the row's own tracker entry (same company and title, dated within 90 days), which is the application itself, not a repost. The saved ranked files carry no Company/Title/Date lines in the new format, so they are not matched. No repost signals were saved in the old files either, so nothing to compare.
